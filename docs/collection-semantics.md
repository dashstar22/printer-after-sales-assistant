# 对话收集内容的受限语义理解

本功能把少量明确的固定表达交给规则，其余需要理解的对话内容交给受限模型提出分类。模型只建议如何理解当前消息；是否接收字段、准备草稿或允许其他业务动作，仍由服务端校验。

**既有验收状态：约定范围已通过。** 2026-11-09 单元／协议回归606项通过；固定24题中，23条真实 `qwen-plus` 分类与1条本地门禁全部通过，0失败、0跳过；隔离HTTP／MySQL集成8项全部通过，模型为本机协议替身。详情见 [最终验收记录](collection-semantics-acceptance-20261109.md)。这些数字对应当时默认关闭的源码快照。

**当前默认行为：受限语义理解开启。** 随后按用户要求，将 `ASSISTANT_COLLECTION_SEMANTICS_ENABLED` 的默认值改为 `true`，使正常收集流程使用内容理解。历史验收记录及逐题证据保留，不能将其中的源码哈希和成绩表述为本次默认值调整后重新运行的真实模型或数据库结果。

本次默认值调整后，相关单元／本机协议回归607项全部通过，0失败、0错误、0跳过；默认开启和显式关闭均通过实际Spring属性绑定及行为验证。改动与运行命令见 [默认开启验证记录](collection-semantics-default-on-20261109.md)。

## 处理范围

- 独立寒暄、能力说明、工单导航以及明确暂停／继续／取消等固定表达保留确定路径。
- 收集中的自由文本、带标签字段，以及通过原有明确准备授权门禁的首次请求所携带字段，在应用前检查用途；不能通过增加“故障：”等标签跳过内容判断。
- 开启新模式时，普通自然语言也可以先分流；无关话题仅引导回售后服务，需要售后知识时进入已有问答流程。
- 多字段候选整体检查，通过后由服务端应用确定解析出的用户原文；模型不输出或改写字段值。
- 部分候选有效、任一候选明确与其字段用途无关时，整条按 `OUT_OF_SCOPE` 拒绝；多个标签字段并存本身不属于事实与提问混合。独立现场事实与提问、猜想或提交意愿不明确仍按 `UNCLEAR` 澄清。
- 有候选字段时，独立固定准备尾句只表示流程意愿，先排除它对字段用途判断的影响；发送给供应商的USER仍是完整原文。独立已发生现象／已执行动作与提问并存时整条澄清，纯问题内部提及所问现象不算另一条独立事实；屏幕引用中的准备字样仍作为观察数据保留。

下面是分类目标与服务端行为示例，不是本轮真实模型实测结果：

| 当前语境与输入 | 目标理解 | 服务端行为 |
| --- | --- | --- |
| 普通聊天：“我喜欢吃汉堡” | OUT_OF_SCOPE | 引导回售后，不建立收集授权 |
| 等待故障：“母猪能上树” | OUT_OF_SCOPE | 不填故障，继续要求设备信息 |
| 等待故障：“故障：我喜欢吃汉堡” | OUT_OF_SCOPE | 标签不能使无关内容直接保存 |
| 等待现场补充：“我换纸后还是卡纸” | FIELD_VALUE | 门禁通过后接收原文 |
| 等待现场补充：“换纸能解决吗” | KNOWLEDGE_QUESTION | 不填成事实，进入知识处理或澄清 |
| “打印机屏幕显示‘我喜欢吃汉堡’” | 可能是设备观察事实 | 判断完整语境，不能用“汉堡”黑名单拒绝 |
| 等待联系方式：“苹果” | 没有可用联系信息 | 格式校验拒绝，不靠模型补造 |
| 混合提问、猜填、注入或无法确定用途 | UNCLEAR | 保留字段并澄清 |

`FIELD_VALUE` 仅表示适合当前字段的用户陈述，不证明现场描述客观属实。模型会误判；只有真实模型评测才能说明指定模型在指定样例上的分类质量。

首次准备报修仍先检查原有明确授权规则。间接转述、否定、条件或包含命令词的复杂引用可能被保守拒绝，分类器不能据此授予收集权限。例如“屏幕显示‘请更换墨盒’，请准备报修”若未通过起始门禁，可先单独发送“请准备报修”，建立授权后再提供现场原文或带标签字段。这种授权前澄清不表示内容分类器调用失败；简单故障前缀和符合起始门禁的明确标签内容仍会接受新语义检查。

## 输出与服务端门禁

解释器只接受以下有限结构，额外字段、重复键、工具调用、非法枚举或截断响应都按失败处理：

```json
{"kind":"FIELD_VALUE"}
```

`kind` 仅允许 `FIELD_VALUE`、`KNOWLEDGE_QUESTION`、`OUT_OF_SCOPE`、`UNCLEAR`。额外 system 上下文只包含服务端确定的待填字段和候选字段名，不放候选值；模型从独立 USER 原文理解实际内容。用户原文作为数据，不能改变分类规则。没有收集授权时，模型不能凭 `FIELD_VALUE` 建立授权。

应用提议前仍检查本人会话与设备、有效收集授权、当前字段、最新 USER 原文、十分钟期限、目标状态和版本。联系方式另有确定性格式检查。字段齐全仍只进入既有草稿准备；建单继续要求页面明确确认及既有幂等事务。

## 配置

| 配置键 | 默认值 | 含义 |
| --- | --- | --- |
| `ASSISTANT_COLLECTION_SEMANTICS_ENABLED` | `true` | 正常使用默认启用内容理解；显式设为 `false` 可关闭 |
| `ASSISTANT_COLLECTION_SEMANTICS_MODEL` | 空 | 空时复用 `AI_CHAT_MODEL`；非空时只覆盖受限分类使用的模型名称 |
| `ASSISTANT_OBSERVATION_SEMANTICS_ENABLED` | `false` | 旧的仅等待 extra 三分类模式；新模式开启时由新模式优先处理 |

开启新模式不等于自动选择轻量模型。独立模型名称必须由操作者选择供应商实际提供且已评估的型号。`qwen-plus` 已通过本固定开发集，尚无独立未见输入效果、轻量模型选型、稳定延迟或人民币费用验证。分类沿用已有 AI 地址、凭证及预算，凭证不放入模型消息或公开日志。

默认开启不会自动启用 AI 或补齐模型地址、凭证；模型仍需有效配置，并受既有调用、字节和超时预算约束。真实 AI 模式下，需要语义判断的输入会产生供应商用量；少量明确固定表达仍由规则直接处理，不增加分类调用。离线模式仍不能用于评价真实模型分类质量。

使用新包且未配置该开关时即默认开启，无需另加 `true`。本机运行器会清理终端中的 `ASSISTANT_` 变量，`init --config` 白名单也不接受这些键。如需显式关闭，可在指定实例私有 `runtime.json` 的已有 `env` 中配置：

```json
{
  "ASSISTANT_COLLECTION_SEMANTICS_ENABLED": "false",
  "ASSISTANT_COLLECTION_SEMANTICS_MODEL": ""
}
```

仅编辑已有 `env` 对象中的相应项，保留其他配置；恢复新模式可改为 `"true"` 或删除该项以使用新默认值。实例绑定初始化时复制的 JAR；重新构建源码不会自动替换已有实例，已绑定旧包或已显式设置 `false` 的实例也不会自动开启。配置在应用重启后生效，构建、实例更新与重启需按 [运行说明](running.md) 核实指定实例后进行。本次未更新或启动日常运行器实例。

## 关闭与失败行为

显式关闭新模式且旧模式也关闭时，需要语义检查的收集候选保持不应用并澄清，不退回“没命中禁词就填入”。仅使用旧 extra 三分类时，必须显式设置 `ASSISTANT_COLLECTION_SEMANTICS_ENABLED=false`，同时设置 `ASSISTANT_OBSERVATION_SEMANTICS_ENABLED=true`；符合旧 extra 入口条件的输入才沿用旧三分类，其他字段、标签及初始携带内容仍不能宽松填入。新模式默认开启并优先处理；新分类失败后不回退旧 extra 路径。旧解释器和冻结评测资产保留，用于兼容和历史证据。

每轮分类最多一次请求、零重试，超时取剩余请求预算与五秒的较小值，并计入已有模型次数和 CHAT 外部调用字节预算。预算不足、超时、协议无效或服务失败时停止分类处理，保持字段不变并澄清；不调用另一个模型补救，不猜填。
