# 架构与行为边界

纸序采用 Spring Boot 单体应用，前端静态页面由同一服务提供。MySQL 保存账号、设备归属、咨询消息、草稿、确认、工单、知识版本、任务及外部调用预算；模型不能作为授权或业务写入结果的来源。

## 从咨询到工单

登录身份来自服务端 Session。订单、咨询、草稿和附件读取执行服务端归属校验。对话规则先处理确定的业务动作，持久化对话状态管理报修收集，模型处理受限的自然语言与知识回答。服务端校验所有工具参数和当前用户身份。

建单前保存完整草稿，再由用户在页面明确确认。确认绑定客户、草稿版本和内容，内容改变使旧确认失效。确认消费、工单创建和首条事件在同一事务内完成；唯一约束与请求标识保证重复提交返回原工单。客服接单后记录负责人，关闭需要非空处理结果；转交保留原因和历史事件。

## 资料发布与检索

管理员上传并核查来源、型号、版本、用途许可和分块。文件提取保留章节和定位，采用递归分块；当前没有父子块扩展。发布以 revision/generation 标识一版输入，通过持久任务、Outbox、RabbitMQ 投递、租约及幂等阶段恢复工作。Qdrant 向量索引与 Lucene 关键词索引均完成核验后才切换有效版本，一路失败保留原有效资料。

查询在型号、有效版本及用途许可范围内完成向量和 BM25 召回，按 RRF 融合并重排。Redis 缓存候选标识，身份包含版本和配置；命中后重新核对当前状态及许可，不缓存并跨用户共享业务正文。引用快照保留当时的资料版本，后续停用不会把旧回答伪装成新知识。

生成只使用经核对且适合预算的证据，要求逐点引用，拒绝非法引用和无效结构。引用标识合法不保证每句话正确，因此仍需逐题质量评测。无依据、需要用户补充现场信息、模型失败与检索故障分别展示；普通表单报修不依赖模型。

## 组件的必要职责

| 组件 | 职责 | 主要保护 |
|---|---|---|
| MySQL | 持久业务与任务状态、预算 | 事务、唯一约束、服务端归属 |
| Qdrant / Lucene | 向量 / 关键词召回 | 型号与有效版本过滤、双索引核验 |
| RabbitMQ | 知识任务投递 | Outbox、租约、幂等与有限重试 |
| Redis | 候选缓存、原子限流 | 版本复核、有限降级保护 |
| LangChain4j / DashScope | 聊天、改写、Embedding 与重排 | 用途许可、超时、调用/字节/并发预算 |
| Mailpit | 本机账号邮件捕获 | 不配置外发，不代表真实邮件送达 |
| MCP / 可选通知流程 | 超时工单与日报只读查询 | 独立身份、固定工具，通知 UNKNOWN 保留待核查 |

本机运行器默认关闭外部通知。公开包包含 MCP 服务端实现；n8n 业务渠道部署及私有凭证需由部署者另行配置。
